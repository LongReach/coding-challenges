Problem: https://leetcode.com/problems/cat-and-mouse/
Difficulty: hard
Solved: yes

Initial Thinking:
========================================================

The state of the whole system can be represented like so:

(mouse_node, cat_node, mouse_turn)

mouse_node: number of node that the mouse is on
cat_node: number of node that the mouse is on
mouse_turn: True if it's the mouse's turn, False if it's the cat's

The opening state would be:

(1, 2, True)

Each possible state can yield a mouse victory, a cat victory, or a draw. If it's the mouse's turn and any child state (a turn the mouse can take) yields a mouse victory, then the current state also yields a mouse victory. If all of the child states yield a cat victory, then the current state yields a cat victory.

The same idea applies in reverse for the cat. When we get a clear victory for a state, we can save this result in a state lookup table to cut down on computation.

Draws are more challenging to determine. Whether a state yields a draw depends on the path taken to get there (the states covered on previous turns), so it's not helpful to save a draw result in the state lookup table. Maybe the draw result will change to a victory if the game reaches the state by some other route.

Solutions
========================================================

Solution idea 1
---------------

I tried a depth-first solution. You keep exploring states recursively, stopping when you've hit a game-ending state or a previously visited one. The trouble is, if there a lot of possible states that can be reached in the game, recursion can go pretty deep without hitting a victory state.

Exploration
---

We do a depth-first search through possible states, starting with opening state.

Example 1 (from webpage):

(1, 2, True)
(3, 2, False)

Cat can go to 4 or 5

If it goes to 4, the resulting sequence will be:

(3, 4, True)
(5, 4, False)
(5, 3, True)
(0, 3, False): mouse victory

If the cat goes to 5 instead, the resulting sequence will be:

(3, 5, True)
(4, 5, False)
(4, 2, True)
(3, 2, False): a draw, players get back to previous state

The cat will always choose a draw over letting the mouse win. The mouse will do the same in reverse.

Solution idea 2:
---------------

What about breadth-first search? If the game can be won by one player or the other within t turns, we find that out by searching every possible state that can be reached within t turns. Each time we resolve a state for one player or the other, we try to resolve its parent states (i.e. any state that's known to lead to it).

If we've covered all the states that can be reached in t turns, then we have to examine the states that can be reached in t+1 turns. We keep going with this until there's no reachable state we haven't considered yet.

Optimizations:
---

Optimization 1: we limit the number of turns. At worst, the mouse travels through all the nodes in the graph to get to the hole.

Optimization 2: we try to explore states that seem MORE LIKELY to lead to a victory before we explore those that are less likely.
